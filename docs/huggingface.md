# Train an ONNX LoRA model with Hugging Face Trainer

Use datasets for batches and Trainer for AdamW, scheduling and checkpoints,
while ONNX executes the model and its derivatives.

```bash
uv sync --group dev --group training --group huggingface
uv run python -m examples.huggingface.trainer --output-dir trainer_models
```

The example reuses the [LoRA regression model](lora.md). The public [`onnax.torch.OnnxModule`](torch.md) owns
only the two trainable adapter tensors. Its custom autograd boundary executes
an ordinary ONNX forward model; backward passes PyTorch's upstream cotangent
into the VJP generated by `onnax.vjp`. PyTorch computes the MSE loss and Trainer
updates the adapters. Frozen weights stay in ONNX initializers.

This separation also supports caller-defined losses, scaled upstream gradients
and gradient accumulation. The bridge snapshots data inputs for backward and
uses PyTorch saved tensors to detect intervening parameter updates. CPU FP32
NumPy/Torch exchange lives at this boundary; the exported graphs have no
PyTorch dependency. Differentiating through the boundary a second time is
currently unsupported.

## Recovery and export

The command runs 200 updates continuously, then interrupts a second run at
update 100. A new Python process loads that Trainer checkpoint and completes
the remaining updates. The final adapter arrays must match byte for byte.
Trainer saves adapter parameters, optimizer moments, scheduler and random state.

`continuous/export-200/forward.onnx` contains the final adapters as initializers.
`adapter.npz` stores adapters by their stable ONNX names, and `interface.json`
records shapes, dtypes, gradient names and artifact hashes. The program
reloads the final ONNX and compares predictions with the independent NumPy
model. `report.json` records loss reduction and recovery results.

Use the same base ONNX and interface when restoring a Trainer checkpoint. The
checkpoint contains the bridge's trainable tensors, while the base model is an
independent asset. The module accepts an ONNXScript optimization callback; ORT graph optimization
is disabled during execution.
