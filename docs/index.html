onnax

JAX-inspired transformations for ONNX graphs. Batch with vmap, differentiate with grad, jvp, and vjp, and save the result as ordinary ONNX. Experimental alpha software.

Extend operator support

Register custom transformation rules once with @onnax.register_jvp, @onnax.register_vjp, or @onnax.register_batching. Import your plugin before calling the usual onnax.jvp(model), onnax.grad(model), or onnax.vmap(model, in_axes=...); no rule argument is needed.

Each registration names a domain, operator, and inclusive opset range. Later registrations override earlier rules, including builtins, within overlapping versions. Each transformation uses a stable snapshot of the current registrations.

Registrations live in the Python process. Exported derivative graphs are ordinary ONNX models; custom primal operators still need an ONNX function or runtime implementation. Run the complete plugin example, which checks JVPs, VJPs, gradients, HVPs, and per-example gradients. Read the callback contracts.

Optimize for deployment

Compose grad, jvp, or vmap first, then optimize a copy with the ONNXScript optimizer. onnax emits compact broadcast derivatives for concrete shapes and retains runtime handling for symbolic dimensions. ONNXScript can fold constants and share work across the complete graph.

For repeated directional products, the optional HoistLinearCoefficientsPass(inputs=["q_tangent"]) can first extract direction-independent coefficients for CSE. This explicitly permits floating-point reassociation; validate numerical behavior for your workload. The pass preserves its source and does not require ONNXScript.

The jelly exporter uses ONNXScript for offline optimization; browser ONNX Runtime graph optimization is disabled. See the export example and validation guidance.
